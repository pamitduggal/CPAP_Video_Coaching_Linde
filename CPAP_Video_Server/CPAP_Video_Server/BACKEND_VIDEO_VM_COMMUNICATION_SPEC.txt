 3. SCENARIO 1: SINGLE-CLIP VIDEO RECOMMENDATION PROTOCOL
================================================================================

Use Case: When an isolated issue (e.g. Mask Leak >= 24 L/min) requires 1 video.

Step 1: Edge Node / Backend calls VM4
--------------------------------------
• Method & URL : POST http://159.84.143.246:8080/api/orchestrate
• Headers      : 
    Content-Type: application/json
    X-API-KEY: <VIDEO_SERVER_API_KEY>

• Request Body JSON:
{
  "patient_id": "191831",
  "title": "Adjust Mask Straps",
  "video_filename": "1_Mask_leak_adjust_straps.mp4",
  "duration_s": 10.0,
  "category": "Mask & Equipment",
  "trigger_reason": "Elevated mask leak detected (CPAP_Leaks95 >= 24.0 L/min)",
  "relevance": "high",
  "thumbnail_type": "technical"
}

Step 2: VM4 processes & forwards assignment to VM2 Dashboard
------------------------------------------------------------
• VM4 resolves the exact video file and matching bilingual subtitles.
• VM4 executes webhook push to: POST http://159.84.143.151:80/api/videos/191831/assign
• VM4 attaches header: X-Video-Server-Key: <VIDEO_SERVER_KEY>
• VM4 Payload sent to VM2:
{
  "patient_id": "191831",
  "title": "Adjust Mask Straps",
  "video_filename": "1_Mask_leak_adjust_straps.mp4",
  "url": "http://159.84.143.246:8080/videos/existing/1_Mask_leak_adjust_straps.mp4",
  "subtitle_en_url": "http://159.84.143.246:8080/subtitles/1_Mask_leak_adjust_straps.en.vtt",
  "subtitle_fr_url": "http://159.84.143.246:8080/subtitles/1_Mask_leak_adjust_straps.fr.vtt",
  "duration_s": 10.0,
  "category": "Mask & Equipment",
  "trigger_reason": "Elevated mask leak detected (CPAP_Leaks95 >= 24.0 L/min)",
  "relevance": "high",
  "thumbnail_type": "technical",
  "storage_bucket": "existing"
}

Step 3: Expected VM2 Response to VM4
------------------------------------
• HTTP Status : 200 OK
• Body        : {"status": "success", "message": "Video 'Adjust Mask Straps' successfully assigned and intervention logged."}

Step 4: VM4 Response back to caller
-----------------------------------
• HTTP Status : 200 OK
• Body        : {"status": "ok", "decision": { ... }, "dashboard_push": "success"}

 4. SCENARIO 2: MULTI-CLIP VIDEO SEQUENCE (VIRTUAL STITCHING) PROTOCOL
================================================================================

Use Case: Multi-step coaching (e.g. Adjust Straps [Clip 1] -> Refit Lying Down [Clip 2]).
Implementation: Virtual Client-Side Stitching (0ms re-encode latency, flawless subtitles).

How Composability is Handled:
• Video 1 JSON metadata specifies:
    "can_precede": [2, 3, 14],
    "transition_type": "fade_1_5s",
    "scenario_fit": ["standalone", "clip_1_of_2"]
• Video 2 JSON metadata specifies:
    "can_follow": [1, 3],
    "transition_type": "fade_1_5s",
    "scenario_fit": ["standalone", "clip_2_of_2"]

Sequential Assignment Delivery Options:
Option A (Standard Sequential Push):
  1. Edge Node calls POST /api/orchestrate for Clip 1 (e.g. 1_Mask_leak_adjust_straps.mp4).
  2. Edge Node calls POST /api/orchestrate for Clip 2 (e.g. 2_Mask_leak_refit_while_lying_down.mp4).

Option B (Sequence Playlist Payload on Dashboard):
  Backend / Dashboard renders an array of video steps:
  [
    {
      "step": 1,
      "title": "Adjust Mask Straps",
      "url": "http://159.84.143.246:8080/videos/existing/1_Mask_leak_adjust_straps.mp4",
      "subtitle_en_url": "http://159.84.143.246:8080/subtitles/1_Mask_leak_adjust_straps.en.vtt",
      "duration_s": 10.0,
      "transition": "fade_1_5s"
    },
    {
      "step": 2,
      "title": "Refit While Lying Down",
      "url": "http://159.84.143.246:8080/videos/existing/2_Mask_leak_refit_while_lying_down.mp4",
      "subtitle_en_url": "http://159.84.143.246:8080/subtitles/2_Mask_leak_refit_while_lying_down.en.vtt",
      "duration_s": 10.0,
      "transition": "end"
    }
  ]

Frontend Playback Rule for Seamless Gapless Stitching:
• Preload the next clip using `<video preload="auto">` in background.
• When Clip 1 hits 9.0s, begin playing Clip 2 with a 1.5s visual CSS opacity crossfade.

 5. SCENARIO 3: AI-GENERATED VIDEO (GOOGLE VEO / VERTEX AI) PROTOCOL
================================================================================

Use Case: When an edge case requires generating a customized video via Generative AI.

Step 1: Edge Node triggers Vertex Generation on VM4
---------------------------------------------------
• Method & URL : POST http://159.84.143.246:8080/api/vertex-generate
• Headers      : 
    Content-Type: application/json
    X-API-KEY: <VIDEO_SERVER_API_KEY>

• Request Body JSON:
{
  "patient_id": "191831",
  "prompt": "Medical 3D animation showing proper CPAP mask seal adjustment while lying in bed",
  "model": "veo-2.0-generate-001"
}

Step 2: VM4 Execution
---------------------
• Submits prompt to Google Vertex AI Veo endpoint via HTTPS TLS 1.3.
• Decodes Base64 video response and saves to `new_videos/vertex_gen_191831_<timestamp>.mp4`.
• Auto-executes `build_video_metadata.py` in background to index the new clip.

Step 3: VM4 Response to Caller
------------------------------
{
  "status": "success",
  "scenario": "scenario_3_hybrid_generated",
  "generated_video_filename": "vertex_gen_191831_1787666761.mp4",
  "vertex_endpoint_used": "https://us-central1-aiplatform.googleapis.com/v1/...:predict",
  "vertex_api_status": "http_200",
  "saved_path": "C:\\CPAP_Video_Server\\new_videos\\vertex_gen_191831_1787666761.mp4",
  "metadata_status": "auto_metadata_indexed"
}

Step 4: Subsequent Assignment to Patient
----------------------------------------
• Once generated, assign to patient via `POST /api/orchestrate` with:
  `"video_filename": "vertex_gen_191831_1787666761.mp4"`
• Stream URL resolved: `http://159.84.143.246:8080/videos/new/vertex_gen_191831_1787666761.mp4`

 7. COMMON ERROR PREVENTION CHECKLIST (HOW TO AVOID FAILURES)
================================================================================

[✓] Error 1: 403 Forbidden on VM4 endpoints (/api/orchestrate, /api/vertex-generate)
    Cause   : Missing or incorrect `X-API-KEY` header.
    Fix     : Ensure caller passes `X-API-KEY: <VIDEO_SERVER_API_KEY>`.

[✓] Error 2: 403 Forbidden on VM2 assignment webhook (/api/videos/{patient_id}/assign)
    Cause   : Missing or incorrect `X-Video-Server-Key` header.
    Fix     : VM4 MUST pass `X-Video-Server-Key: <VIDEO_SERVER_KEY>`.

[✓] Error 3: Video plays in browser but Subtitles do NOT appear
    Cause   : Cross-Origin Track Blocking by browser.
    Fix     : Add `crossorigin="anonymous"` (or `crossOrigin="anonymous"` in React)
              to the `<video>` HTML element.
              Example:
              <video controls crossorigin="anonymous" src="http://159.84.143.246:8080/videos/existing/1_Mask_leak_adjust_straps.mp4">
                <track kind="subtitles" src="http://159.84.143.246:8080/subtitles/1_Mask_leak_adjust_straps.en.vtt" srclang="en" label="English" default />
                <track kind="subtitles" src="http://159.84.143.246:8080/subtitles/1_Mask_leak_adjust_straps.fr.vtt" srclang="fr" label="Français" />
              </video>

[✓] Error 4: 404 Video File Not Found
    Cause   : Filename typo or missing `.mp4` extension in `video_filename`.
    Fix     : Ensure `video_filename` matches exact filename in `existing_videos/`
              (e.g., "1_Mask_leak_adjust_straps.mp4", NOT "1_Mask_leak").

[✓] Error 5: 404 Subtitle Track Not Found
    Cause   : Constructing subtitle URL with `.mp4.en.vtt`.
    Fix     : Subtitle URL stems use `.en.vtt` and `.fr.vtt` directly
              (e.g., "1_Mask_leak_adjust_straps.en.vtt").

[✓] Error 6: 403 Security Probe Block
    Cause   : Calling administrative probe paths (e.g. `/.env`, `/.git`, `.php`).
    Fix     : Only call declared `/api/*`, `/health`, `/videos/*`, `/subtitles/*` routes.

[✓] Error 7: Timeout connecting to port 8080
    Cause   : Firewall rule blocked.
    Fix     : Windows Firewall rule `Allow Uvicorn 8080` is open to all client IPs (`RemoteAddress: Any`).
